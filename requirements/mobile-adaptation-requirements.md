# SubVault 移动端适配需求规格

## 1. 目标

使 SubVault 前端在主流手机视口下具备完整、清晰、可操作的使用体验，同时保持现有桌面端布局、业务功能、数据行为与后端接口兼容。

## 2. 范围

### 2.1 范围内

- 登录与二步验证页面。
- 登录后的全局布局与导航，包括服务订阅、凭证管理、备忘录、数据分析、智能助手、设置，以及导入、导出和锁定入口。
- 各页面的标题区、操作区、卡片、列表、表格、筛选与视图切换控件。
- 所有新增、编辑、详情、导入、AI 解析、配置和确认类弹窗。
- 空状态、加载状态、错误状态及长文本、较多数据等内容边界场景。
- 触屏操作、移动端滚动、软键盘出现时的表单可用性。

### 2.2 范围外

- 新增或改变业务功能、业务流程、数据模型、接口协议和权限规则。
- 原有视觉品牌的整体重设计。
- 原生 iOS/Android 应用、PWA 离线能力或移动端专属后端接口。
- 平板或桌面端功能删减。

## 3. 功能要求

1. 在手机视口中，全局导航必须可发现、可打开、可关闭，并能访问现有全部页面及导入、导出、锁定操作；导航不得永久占据导致主内容不可用的水平空间。
2. 页面标题、说明、主要操作和筛选控件必须根据可用宽度合理换行或重排，不得互相遮挡或超出视口。
3. 订阅、凭证、备忘录、分析和设置内容必须在窄屏中保持信息可读、操作可触达；多列内容应按窄屏阅读顺序重排。
4. 凭证表格等天然宽内容必须提供适合手机的可用呈现，关键字段和查看、编辑、删除等现有操作不可丢失。
5. 所有弹窗在手机视口中必须完整落入可视区域；内容较高时可滚动，标题、关闭入口、表单字段和提交/取消操作均可触达。
6. 表单输入在软键盘打开时仍可查看当前字段并完成提交；触控目标之间应有足够间距，避免误触。
7. 长用户名、网址、标签、备忘录内容及 AI 输出不得撑破布局；需要截断时，仍须保留查看完整内容的既有路径。
8. 页面不得出现由整体布局造成的非预期水平滚动；明确需要横向浏览的数据区域可在自身容器内滚动。

## 4. 兼容与约束

- 以宽度 320px 至 767px 的手机视口为移动端验收区间，至少覆盖 320×568、375×667、390×844、430×932 四组代表性视口，并覆盖竖屏；横屏不得出现内容不可恢复或关键操作不可达。
- 保持 768px 及以上现有平板/桌面体验和功能向后兼容，不引入明显布局回归。
- 保持现有中文文案、品牌风格、业务行为、状态管理、数据格式和后端 API 契约不变。
- 继续满足现有键盘焦点、语义和减少动态效果等可访问性行为；移动端适配不得使其退化。
- 不得以隐藏关键内容或移除现有操作作为适配手段。

## 5. 关键验收标准

1. 在上述四组代表性手机视口逐页检查登录、二步验证和六个登录后页面，页面级水平溢出为零，文字、控件和内容无重叠、裁切或不可读情况。
2. 在手机上可从任意登录后页面访问全部导航项，并可执行导入、导出、锁定；打开导航后能明确关闭或在完成跳转后回到内容区。
3. 订阅、凭证和备忘录的新增、查看/编辑、删除等现有核心流程在手机视口中可完成；对应弹窗的所有字段与底部操作均可滚动到达。
4. 凭证卡片/表格视图、页面筛选、视图切换和主要操作在窄屏中均可使用，关键操作不因重排而缺失。
5. 分析、AI、设置页面在窄屏中可完整浏览和操作；图表、代码/长文本、配置表单不会撑破页面。
6. 桌面代表性视口 1440×900 下，原有导航、页面布局和全部现有业务入口保持可用，无明显视觉或交互回归。
7. 前端现有自动化测试与构建通过；新增适配应提供覆盖关键响应式行为的验证证据，并附手机与桌面代表性视口的页面截图或等效浏览器检查结果。

## 6. Definition of Done

- 范围内页面、组件和弹窗均完成移动端适配，并满足关键验收标准。
- 320px 宽度下不存在阻断操作的布局问题；375px、390px、430px 宽度下体验稳定。
- 所有既有业务入口和核心流程在移动端与桌面端均可用，后端与数据契约未改变。
- 构建和现有测试通过，浏览器视口验证覆盖至少一个 320px 视口、一个主流手机视口及 1440px 桌面视口。
- 验证记录能够明确对应页面、视口、操作路径和结果；已知非阻断问题需单独列明，不得以未记录的假设代替验收。
